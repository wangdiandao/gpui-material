# Components

English | [中文](component.zh.md)

These components and layouts are available from `gpui_material`. Enable the named [features](#optional-components) to use the optional component families. See the [integration guide](integration.md) for setup and platform support, or run `cargo gallery` to try interactive examples.

The [pinned Material 3 specification](design-sources.md#material-specification) governs component design. The links below point to the corresponding official guidance. [Site snapshots](material-snapshot.md) record the version used by the project.

## Actions and selection

| Component | Supported variants and behavior | Material 3 |
| --- | --- | --- |
| `Button`, `ToggleButton` | Elevated, Filled, Filled Tonal, and Outlined. `Button` also has a Text variant. Both support XS–XL sizes, round or square shapes, custom content and appearance, and optional interaction observation. | [Buttons](https://m3.material.io/components/buttons/overview) |
| `IconButton`, `IconToggleButton` | Standard, Filled, Filled Tonal, and Outlined, with selectable sizes and widths, per-instance shapes, colors and stroke, and optional interaction observation. | [Icon buttons](https://m3.material.io/components/icon-buttons/overview) |
| `Fab`, `ExtendedFab` | Small, Medium, and Large sizes with multiple color roles. `ExtendedFab` supports a text label and an icon. | [FAB](https://m3.material.io/components/floating-action-button/overview) · [Extended FAB](https://m3.material.io/components/extended-fab/overview) |
| `Checkbox` | Unchecked, checked, mixed, error, and disabled states, with per-instance colors, strokes, and interaction observation. | [Checkbox](https://m3.material.io/components/checkbox/overview) |
| `Radio`, `RadioGroup` | Mutually exclusive selection, group keyboard navigation, per-option colors, and optional interaction observation. | [Radio button](https://m3.material.io/components/radio-button/specs) |
| `Switch` | On and off states with optional thumb icons or custom content, per-state colors, and shared interaction observation. | [Switch](https://m3.material.io/components/switch/overview) |
| `Chip` | Assist, Filter, Input, and Suggestion, with content slots, custom appearance, and independent selection and removal where applicable. | [Chips](https://m3.material.io/components/chips/overview) |
| `Slider` | Single-value, centered, and range sliders with custom tracks, handles, and indicators. Supports horizontal and reversible vertical layout, with continuous or stepped values. | [Sliders](https://m3.material.io/components/sliders/specs) |

Use `.content(element)` to customize the rendered label while retaining the constructor's accessible name and any leading or trailing icon slots. Keep the content free of independent controls so the button owns activation and focus. Set `.shapes(ButtonShapes)`, `.colors(ButtonColors)`, `.border(ButtonBorder)`, `.content_padding(ButtonPadding)`, and `.elevations(ButtonElevations)` per instance. Unspecified shape, color, and elevation fields keep the size and variant defaults for that state. `ButtonPadding` follows the window's text direction. A zero-width border removes the default outline.

Pass a decorative icon element and an accessible name to `IconButton::new` or `IconToggleButton::new`. Icon buttons default to the Small size, Uniform width, Round shape, and Standard palette. Use `.shapes(ButtonShapes)` for resting and pressed corners and for checked corners on toggles. `.colors(ButtonColors)` supplies container and icon colors for enabled, disabled, and checked states. Omitted fields use the current size and variant defaults. `.border(ButtonBorder)` replaces the default stroke. Use zero width to remove it. `IconToggleButton` renders the caller's selected value and uses `.selected_icon(element)` when selected, if supplied.

Keep an `Entity<InteractionSource>` in the caller and attach it with `.interaction_source(&source)` to observe a button or icon button. Give each control sharing a source a distinct element ID within its window. Read the current state with `InteractionSource::state`, or subscribe to `InteractionUpdate` for each deferred change, including press and release between draws. A removed control clears its snapshot. Base still owns input handling and the application owns toggle values.

### Floating action button

`Fab::new` takes an icon and an accessible name. It defaults to a 56 dp Small FAB in the primary container palette. Give each Small, Medium, or Large instance its own `.shape(CornerShape)`, `.colors(ButtonColors)`, and `.elevations(ButtonElevations)`. Use the container and content fields for enabled and disabled colors. Omitted fields keep the size and palette defaults. Use `.interaction_source(&source)` to observe the action with a caller-owned source.

Keep the visibility flag in application state and pass it with `.visible(visible)` on each render. Use a stable element ID between updates so the two motion channels can reverse from their current progress. `FabVisibilityAnimation` defaults to center alignment, a hidden scale of `0.2`, and the theme's Fast Spatial and Fast Effects motion for scale and alpha. Use logical `FabAlignment` positions to scale about an edge or corner that mirrors in right-to-left windows. Set `target_scale` to a finite nonnegative value and set `scale_motion` and `alpha_motion` independently. Invalid scales, including values that overflow the scaled extent, fall back to `0.2`. Reduced motion applies the final state immediately.

A hiding FAB stops taking focus and input immediately. It occupies its layout space while fading and gives up that space at zero opacity. An initially hidden FAB takes no space. Keep the icon decorative so the FAB owns activation and focus. Use inherited text sizing or relative dimensions for custom icons that should resize during the transition.

### Checkbox

`Checkbox::new(id, label, state)` renders the caller's state. Pointer, keyboard, and accessibility activation request the next value through `.on_change`. Activating a mixed checkbox requests `Checked`. Apply the request in the owner and pass the current state on the next render. `.error(true)` exposes the validation state and uses `Error` and `OnError` by default. Disabled appearance takes precedence over error appearance.

Use `.colors(CheckboxColors)` to set `CheckboxStateColors` for each unchecked, checked, or indeterminate state, including error and disabled states. Each state can override its `checkmark`, `box_color`, and `border` independently. Omitted fields keep the window theme's defaults. In the unchecked state, checkmark color applies while the mark retracts.

Set `.checkmark_stroke(gpui::StrokeOptions)` for the uniform checkmark and mixed mark stroke, including width, caps, and joins. Use `.outline_stroke(width)` for the rounded box outline in logical pixels. Both widths default to two logical pixels. A zero width removes that stroke. Negative or non-finite widths use the default, and large widths are bounded by the indicator size. Use a caller-owned `Entity<InteractionSource>` with `.interaction_source(&source)` to observe hover, press, keyboard focus, and disabled state. The source can be shared with other controls using distinct IDs and leaves the value with the caller.

### Radio buttons

Use `Radio::colors(RadioColors)` to override the indicator's selected, unselected, disabled-selected, and disabled-unselected colors independently. Unspecified fields use the current window palette. Selected defaults to Primary, unselected defaults to On Surface Variant, and both disabled defaults use On Surface at 38% opacity.

Pass `.interaction_source(&source)` to observe a standalone radio or individual options in a `RadioGroup`. Grouped snapshots use the rendered ID `ElementId::from((group_id, option_id.to_string()))`, so groups can share one `Entity<InteractionSource>`. Removing an option or replacing its source clears its snapshot in the old source. The caller owns selection and applies `.on_select(...)` requests. A group has one Tab stop, skips disabled options, and mirrors horizontal navigation in RTL.

### Switches

Pass the application's current value to `Switch::new(id, label, checked)` and handle the requested next value with `.on_change(...)`. Pointer, keyboard, and accessible activation request the same change. `.disabled(true)` prevents user changes. The constructor's label provides the visible label and accessible name.

Use `.checked_icon` and `.unchecked_icon` for optional icons, or pass a decorative GPUI element through `.thumb_content(element)`. The custom element takes precedence for that render. Choose it from the caller's checked value to show different elements in each state. Custom content sits in a centered 16 px slot and inherits the state's content color. Keep labels and independent controls outside the thumb.

Use `.colors(SwitchColors)` to configure each `SwitchStateColors` palette for checked, unchecked, disabled checked and disabled unchecked states. Each palette can override `track`, `border`, `thumb` and `content` independently. Omitted fields retain the theme defaults. Attach a caller-owned `Entity<InteractionSource>` with `.interaction_source(&source)` to observe hover, focus, press and disabled changes while the application continues to own the checked value.

### Chips

`Chip::new(id, label)` uses the label as its accessible name. Use `.content(element)` to replace the displayed label in any variant and `.leading_icon(element)` for a leading icon. Input chips accept `.avatar(element)`, a 24 dp circular slot that takes precedence over the leading icon. `.trailing(element)` adds visual content to an Assist, Filter, or Input chip. When a Filter or Input chip has `.on_remove(...)`, that content becomes the removal button's visual label and the removal action keeps its separate accessible name and focus stop. Without custom trailing content, removal uses the Close icon. Keep all visual slot content free of independent controls.

Filter and Input render the owner's `.selected(value)` and request changes through `.on_change`. Assist and Suggestion use `.on_activate`. Removal invokes only the removal callback. `.disabled(true)` disables both actions. Leading and trailing content and removal position mirror in RTL. Keyboard traversal reaches the main action before removal.

`.tonal(true)` selects the expressive Tonal defaults for Filter, elevated Filter, and Input. These presets use Medium resting, Full selected, and Small pressed corners and the theme's `OnSurfaceVariant` for the unselected leading icon. The normal constructor retains the current flat Assist and Small corners. Use `.shapes(ButtonShapes)` to set corners by state. Set `.colors(ChipColors)` with a `ChipStateColors` entry for enabled, selected, disabled, or disabled-selected appearance. Each entry can set the container, label, leading, trailing, and border colors. Missing fields use the chosen variant's defaults, with disabled-selected fields falling back to disabled overrides.

Use `.border(ButtonBorder)` to change the outline width and its fallback color. A zero width hides the outline. `.elevations(ChipElevations)` overrides rest, press, focus, hover, drag, and disabled shadow levels. `.dragged(bool)` reflects an application-owned drag and cancels the pending pointer activation; the application owns the gesture. `.spacing(width)` sets the horizontal gap between content slots, and `.content_padding(ButtonPadding)` sets logical inner edges. The default gap is 8 dp, label-only edges are 16 dp, icon edges are 8 dp, and the avatar starts at 4 dp.

Give each chip a distinct ID and use a caller-owned `Entity<InteractionSource>` with `.interaction_source(&source)` to observe the main action by that ID. The source reports hover, press, keyboard focus, dragged, and disabled feedback; selection and removal remain controlled by the caller.

### Sliders

Retain the `SliderState` entity in the owner. Base manages the range and step grid. `SliderEvent::Change` reports value edits, and `SliderEvent::Release` reports the end of a pointer gesture. Use `Slider::range` with a range value and two accessible names. `.kind(SliderKind::Centered)` fills from the midpoint for single values. `.axis(Axis::Vertical)` runs from bottom to top by default. Set `.reverse_vertical(true)` for top-to-bottom layout, pointer movement, and Up and Down keys. Horizontal layout and keys follow the window direction. Accessibility values and bounds use the numeric order in either orientation.

`.track_style(SliderTrackStyle)` sets `thickness`, `outer_radius`, `inner_radius`, and `thumb_gap` in logical pixels. Omitted fields use the size's default thickness and outer radius, a 2 dp inner radius, and a 6 dp gap from each handle edge. Use `.thumb_style(RangeThumb, SliderThumbStyle)` for each handle's `size`, `pressed_width`, `color`, `disabled_color`, and `focused_color`. Size uses the first dimension along the value axis and the second across it. The default handle is 4 dp along the axis, narrows to 2 dp when dragged, and uses the chosen size's cross-axis extent. Non-finite dimensions and nonpositive sizes use the defaults. Zero is valid for radii and gaps. Use `RangeThumb::End` for a single-value slider.

`.colors(SliderColors)` supplies enabled and disabled colors for the thumb, active and inactive track, and active and inactive ticks. Unspecified fields use the window palette. The enabled thumb and active track use Primary, the inactive track Secondary Container, and the ticks On Primary and On Secondary Container, respectively. Disabled defaults use On Surface at 38% for the thumb, active track and ticks, and 12% for the inactive track. Per-thumb colors take precedence over slider colors. Default keyboard-focus color is Secondary. Use `.thumb(RangeThumb, element)` and `.track(element)` for decorative content in place of the default handle and track. Keep independent controls out of these slots so the slider owns input, focus, and accessibility. When supplying a custom track, draw its own inset icon, ticks, and stops if needed.

`.tick_intervals(count)` controls visual intervals independently of Base's steps. `.draw_ticks(...)` and `.draw_stop_indicators(...)` receive each `SliderMarker` with its window position and default color and diameter, where the default diameter is 4 dp. `.show_stop_indicators(false)` hides stops. The value indicator defaults to visible for the dragged or keyboard-focused handle and displays two decimal places. Use `.value_indicator(false)` to turn it off and `.format_value(...)` to format a live value for display.

`.interaction_source(RangeThumb, &source)` observes each handle independently. The keys are `ElementId::from((slider_id, "start"))` and `ElementId::from((slider_id, "end"))`. One source can observe both keys, or each handle can use its own source. Removing a handle or replacing its source clears the previous snapshot.

### Surfaces

`Surface::new(role)` supplies a passive background. For custom controls, use `Surface::clickable(id, label, role)` or `Surface::selectable(id, label, role, selected)` with `.on_activate(...)`. Use `Surface::toggleable(id, label, role, checked)` with `.on_checked_change(...)`. The label names the interactive surface, and the owner supplies the current selected or checked value on each render. Pointer, Enter, Space, and accessibility actions call the same handler. `.disabled(true)` turns off activation and skips the surface in Tab navigation. Give each surface a stable ID and keep independent actions on their own surfaces. Group related selectable surfaces in a named `gpui::Role::ListBox`.

Surface uses the theme foreground paired with its background role. Roles without a matching foreground and colors set by `.container_color(color)` inherit the current foreground. Use `.inherit_content_color(true)` to inherit across a paired role or `.content_color(color)` to override it. The resulting color flows to descendants through GPUI text style, including Material text and icons without their own color.

Use `.shape(CornerShape)` for logical corners and `.border(SurfaceBorder { width, color })` for a stroke in logical pixels. These settings apply to the background, outline and feedback. Other GPUI Styled layout and paint settings remain available. GPUI clips overflowing children with a rectangular content mask. `.tonal_elevation(Elevation)` tints a theme Surface background, and `.shadow_elevation(Elevation)` sets the shadow independently.

Interactive surfaces use the Material state layer, bounded ripple and keyboard focus ring. `.feedback(SurfaceFeedback)` configures those effects and their colors for a single surface. Attach `.interaction_source(&source)` to observe hover, press, keyboard focus and disabled state. `.track_focus(&focus)` uses a caller-owned focus handle. Reduced motion uses static press feedback.

### Cards

Use `Card::new(id).variant(CardVariant::Elevated)`, `Filled`, or `Outlined` for the current Material variants. Static cards group their content without taking keyboard focus. `.on_activate(name, callback)` gives the card a named action and keyboard focus. Child controls keep their own actions. `.disabled(true)` disables the card action and supplies disabled colors to the card and its inherited content.

Set `.shape(CornerShape)` for the container, border, shadow, and feedback. It follows the window's writing direction. Use `.border(CardBorder { width, color })` for a custom stroke. A width of zero removes the stroke. `.colors(CardColors)` independently overrides enabled and disabled container and content colors. `.elevations(CardElevations)` independently overrides resting, pressed, focused, hovered, dragged, and disabled shadow levels. Omitted fields keep the variant defaults, including Medium corners, an outline on Outlined cards, and flat Outlined cards on hover. Disabled elevation takes priority, followed by drag, press, keyboard focus, hover, and rest.

Set `.dragged(bool)` from the caller's drag lifecycle, including completion and cancellation. A drag interrupts a pending pointer activation. Pass `.interaction_source(&source)` to observe the card through a shared `Entity<InteractionSource>`. Give each observed card a distinct ID within its window.

### Divider

`Divider::horizontal()` and `Divider::vertical()` default to one logical pixel in the window theme's `OutlineVariant` color. Use `.thickness(px(2.))` to set a different logical width or `.thickness(px(0.))` for a one-device-pixel hairline. Invalid thickness values fall back to the default. A vertical divider fills the available height of its parent.

Use `.color(ColorRole::Primary)` to resolve a role against the window theme or `.color_override(hsla)` to use a literal color. The last color setter takes precedence. `.inset(start, end)` follows the window's text direction for horizontal dividers and applies to the top and bottom for vertical dividers. The divider is decorative and adds no focus stop.

### Badges

`Badge::dot(host)`, `Badge::label(host, text)`, and `Badge::count(host, count, maximum)` anchor a mark to the host's upper trailing edge. Pass the current count and cap when rendering. Counts above the cap display the cap followed by `+`. `Badge::standalone()` renders a dot in the surrounding layout. Use `.content(id, element)` to supply a short visual element for either placement. Give each custom mark a stable ID within its parent.

Container and content colors default to the window theme's `Error` and `OnError` roles. Use `.container_color(color)` and `.content_color(color)` to set either independently. Keep custom content noninteractive and let the host's accessible name describe the anchored badge. For a standalone indicator that conveys information on its own, use `.accessible_label(id, label)` to give it a name without adding a focus stop.

### Swipe to dismiss

Keep an `Entity<SwipeToDismissState>` per item and pass it to `SwipeToDismiss::new(id, &state, content)`. The state starts at rest. Use `.initial_value(value)` when restoring an item at a dismissal anchor. Add a background with `.background(element)`. It fills the container behind the moving foreground. Observe the state to update the background with the logical `dismiss_direction()`, signed `offset()` in logical pixels, or outward `progress()` from 0 to 1. `current_value()` is the nearest anchor, `target_value()` is the expected landing anchor, and `settled_value()` changes when the movement completes.

Both logical directions and gestures are enabled by default. Use `.enable_start_to_end(bool)`, `.enable_end_to_start(bool)`, and `.gestures_enabled(bool)` to configure them. The window's writing direction determines the physical swipe direction. The default threshold is 56 logical pixels. Use `SwipeToDismissState::positional_threshold(|width| ...)` to compute a threshold from the laid-out width. Finite results are clamped to the available travel and invalid values use the default. Vertical drags and scroll continue through the surrounding layout.

`dismiss(direction, window, cx)` animates to an enabled direction, `reset(window, cx)` animates back to the resting position, and `snap_to(value, window, cx)` moves immediately. Reduced motion settles immediately. `.on_dismiss(|direction, window, cx| ...)` runs once when movement settles in a new dismissal direction. The foreground leaves keyboard traversal and the accessibility tree at that point. The application owns data changes such as removing the item, and can call `reset` to show it again. Provide a named, keyboard-focusable button or menu item for each offered action. Its activation calls the same `dismiss` method and remains available when gestures are disabled.

### Progress indicators

Create a `LinearProgress` or `CircularProgress` with a stable ID and accessible name. The caller owns the measured value and passes it with `.value(fraction)`. Finite values are clamped to `0..=1`. Omit the value or call `.indeterminate()` to show unspecified progress. Non-finite values also select indeterminate mode. The accessible progress bar reports the current target percentage in determinate mode and has no numeric value in indeterminate mode.

Use `.shape(ProgressShape::Wavy)` for a wavy active indicator. Each mode accepts `.active_stroke(ProgressStroke)`, `.track_stroke(ProgressStroke)`, and `.gap(size)`. Each stroke specifies its own optional width and color and a `ProgressCap` of Round, Butt, or Square. Defaults are 4 dp round strokes, a 4 dp gap, and the window's `Primary` and `SecondaryContainer` colors. Width zero hides that stroke. Negative or non-finite widths and gaps use their defaults. The renderer fits the strokes to the available bounds and limits gaps to the available track. Linear geometry follows the window's layout direction. Circular progress starts at the top and sweeps clockwise.

Use `.wave_amplitude(fraction)` or `.wave_amplitude_by(|progress| …)` to select the wave's height within the available space. The callback receives the displayed progress in determinate mode and zero in indeterminate mode. Amplitude is clamped to `0..=1`, and NaN becomes zero. The default suppresses the wave through 10% and from 95% in determinate mode, and uses full amplitude in indeterminate mode. The measured endpoints at zero and 100% are flat. `.wavelength(length)` sets crest spacing in logical pixels. The circular renderer fits a whole number of waves around the ring. `.wave_speed(length_per_second)` sets the travel speed in logical pixels per second and defaults to one wavelength per second. Zero speed holds the current phase, and invalid lengths or speeds use their defaults. Reduced motion holds a static shape and applies measured changes immediately.

Linear determinate progress has a 4 dp stop marker at the logical track end. Use `.stop_size(size)` to resize it, or zero to hide it. Invalid sizes use the default. Keep a visible stop marker when the track contrasts with its surrounding surface by less than 3:1. `.draw_stop_indicator(|stop, window, cx| …)` replaces the default paint. `ProgressStop` provides the marker bounds, active color and cap, and layout direction. The renderer runs only for a visible stop, is clipped to its bounds, and adds no accessibility node.

### Loading indicator

`LoadingIndicator::new(id, label)` uses a 48 dp footprint and a seven-shape indeterminate loop. Add `.contained(true)` for a rounded container. The Default indicator uses the window's `Primary` color. Contained uses `OnPrimaryContainer` for the indicator and `PrimaryContainer` for the container. Override either indicator with `.indicator_color(color)`. Set `.container_color(color)` and `.container_shape(CornerShape)` on Contained instances. Start and end corners follow the window's layout direction.

The application owns determinate progress. Pass it as `.value(fraction)` on each render. The fraction is clamped to `0..=1`, and NaN becomes zero. With the default sequence, zero shows a circle and one shows the Soft Burst shape. Create a reusable `LoadingIndicatorShapes` with at least two `LoadingIndicatorShape` values and pass it by reference with `.shapes(&shapes)`. Use `LoadingIndicatorShape::circle()` or `LoadingIndicatorShape::rounded_polygon(&vertices, radius)` with GPUI points and a radius in the same units. Polygon construction returns `None` for non-finite, degenerate or self-intersecting geometry. The sequence constructor returns `None` if given fewer than two shapes. A determinate sequence goes from first to last, and an indeterminate sequence also morphs from last to first.

The label names a progress indicator. Determinate mode exposes a numeric percentage and draws the supplied value directly. Indeterminate mode exposes no numeric value and uses a polite live status. Reduced motion holds the first indeterminate shape and keeps determinate progress responsive. `.active(false)` retains the footprint and suppresses visuals and progress semantics. Only an active indeterminate indicator in an active window requests animation frames.

### Snackbars

Retain a window's `Entity<SnackbarHost>` and mount it in the layout or pass it to `Scaffold::snackbar`. Call `push` to append a `Snackbar::new(message)` to the FIFO. A plain message lasts four seconds. `.action(label, callback)` makes it persistent by default. Set `.timeout(Some(duration))` after `.action(...)` to override that duration, or `.timeout(None)` to wait for a dismissal. Each timer starts when its message becomes current.

Set `.message_content(|window, cx| ...)` to replace the visible message. `Snackbar::new` still supplies the accessible status text. Use `.action_content(...)` with `.action(...)` to replace the named action's visible content. `.dismiss_content(label, |window, cx| ...)` replaces the named close control's content. The close icon is shown by default, and `.show_dismiss(false)` hides the affordance. Keep slot content decorative so the host owns focus, activation, and the completion path. `.action_on_new_line(true)` puts the action and optional close control on a trailing-aligned row below the message.

Use `.shape(CornerShape)` for the container and `.colors(SnackbarColors)` to set the container, message content, action, and dismiss colors independently. The default corner radius is 4 dp. The window defaults use Inverse Surface for the container, Inverse On Surface for message and dismissal content, and Inverse Primary for the action. The host renders the message as a polite live status without moving keyboard focus. The named controls use normal Tab traversal and activation. Escape dismisses the snackbar when one of its controls has focus. Completing a focused snackbar restores the prior focus target when it is available.

Use `enqueue` when the caller needs a `SnackbarId`. `current()` returns the active ID and message, and `dismiss()` dismisses the current message. `dismiss_message(id, window, cx)` and `perform_action(id, window, cx)` apply only to the active entry. `perform_action` also requires an action. Use `.on_result(|result, window, cx| ...)` to observe `SnackbarResult::ActionPerformed` or `SnackbarResult::Dismissed`. Timeout and explicit or programmatic dismissal report `Dismissed` and call `.on_dismiss(...)` when supplied. Each result is delivered once. The queue advances before callbacks run, so callbacks can enqueue or dismiss messages from the same host. Dropping the host cancels its timer and discards remaining messages.

`SnackbarHost::renderer(|message, parts, window, cx| ...)` can lay out the provided `SnackbarParts` within a custom container. Place `parts.message` to retain the live status and `parts.action` and `parts.dismiss` to retain the named controls. The host still owns timing, completion, motion, and outgoing content. During exit, the parts render as passive content. The `scale` field lets the renderer scale its own dimensions to match the animation.

### Display-only scrollbar

Create `DisplayScrollbar::new(id, axis, &handle)` with the `ScrollHandle`, `UniformListScrollHandle`, or `ListState` already bound to the viewport. These implement Base's `ScrollbarHandle`. Mount the scrollbar after the viewport as an overlay child of the same relative parent. The viewport retains scroll state, focus, and input. The indicator contributes paint only. In a horizontal layout, progress runs from the logical start to the end. In a vertical layout, the track is on the logical trailing edge. Its position follows the window direction in RTL.

Use `.style(DisplayScrollbarStyle)` to set `thumb_color`, `track_color`, `thickness`, `thumb_min_length`, `thumb_max_length_fraction`, `main_axis_track_inset`, and `cross_axis_track_inset`. The default thumb is the window's Outline at 70% opacity and the track is transparent. Thickness is 4 logical pixels, minimum thumb length is 24 logical pixels, and maximum thumb length is 90% of the track remaining after insets. The main-axis inset is 2 logical pixels at both ends and the cross-axis inset is zero. The indicator hides when content fits the viewport or the track cannot fit the thumb's minimum length. `.offset(point(dx, dy))` moves the painted scrollbar in physical logical pixels inside the viewport clip.

`.fade(DisplayScrollbarFade { enabled, delay, duration })` controls visibility after an offset change. Fading starts enabled with a 400 ms idle delay and a 250 ms fade. Use `enabled: false` to keep the indicator visible while content overflows. Reduced motion keeps the delay and hides it instantly at the end. The viewport schedules ordinary redraws as its offset or extent changes. The indicator schedules a wake-up for the fade delay and requests frames during the fade.

### Exposed dropdowns

Create `ExposedDropdownState` once per dropdown. It owns the pending query, committed selection and list position. Read the displayed visibility with `is_open()` and the last committed option ID with `selected_option_id()`. `with_editor(&editor, editable, window, cx)` uses the caller's retained `TextFieldState`. `.editor(|field| ...)` customizes or wraps the supplied `TextField`, including its label, decoration and editor layout. Keep this field in the result to retain its accessible name and native editing, caret and IME behavior.

The default editable field opens on typing or via its trailing trigger and keeps editor focus. The default selection-only field opens on a click or Space and also retains its field focus. Use `.primary_anchor(DropdownAnchor::PrimaryEditable)` to add whole-field activation while keeping editor focus. Use `PrimaryNotEditable` with selection-only state to move focus to the list and return it to the field on dismissal. `.secondary_anchor(label, |open| ...)` customizes the trailing trigger and supplies its accessible name. Secondary pointer activation keeps the editor available for typing, and accessibility activation of an editable secondary anchor moves focus to the options. `.primary_anchor_enabled(false)` and `.secondary_anchor_enabled(false)` turn off their respective menu activation while leaving editor input available.

Add `.open(open)` and `.on_open_change(|requested, window, cx| ...)` to control visibility. Apply requests in the owner and render again. `.on_dismiss(...)` reports a user request to close. Programmatic updates apply immediately on render and preserve the committed value when discarding the draft. Up and Down navigate options, Enter commits, and Escape dismisses after composition is complete. Focus returns from the menu to its invoking anchor when available. Dismissal leaves focus with an outside control that already received it.

Options retain their IDs across recreation and reordering. `.option_content(|option, highlighted, window, cx| ...)` supplies decorative row content. The original label provides the accessible name and searchable text. Use `scroll_state()` to read or move the retained GPUI `ListState` or `set_scroll_state(&scroll, cx)` to attach one owned by the caller. The viewport constructs only visible rows and overscan, including custom content. Menu width matches the field by default. Use `.match_anchor_width(false)` for an independent width, which defaults to 240 px, and `.popup_width(width)` to override it. Width and height fit the available window area. `.appearance(MenuSurfaceStyle)` configures the menu shape, theme roles, outline and elevations. `.container_color(color)` overrides its container tint.

### Menu controls and item content

`Menu::new` owns its visibility by default. Add `.open(open)` and `.on_open_change(|requested, window, cx| ...)` to let the caller own it. Apply the requested value when desired and render again. A caller update to `open` applies visibility and focus without sending change callbacks. `.on_dismiss(|window, cx| ...)` reports a close request from a user action. `Menu::composed` supplies the displayed open value and an activation callback to a custom trigger.

Keep each `MenuItem` ID stable and provide a label for accessibility. Its `.content`, `.leading`, `.supporting`, `.trailing`, and `.selection_icon` builders accept repeatable element factories for visual content. A menu row owns the keyboard and pointer action. Pass the checked value with `.checked(value)` and handle requests with `.on_checked_change`. Selected items continue to use `.selected(value)` with `.on_activate`.

Use `.color(MenuColor::Vibrant)` for the tertiary menu palette. A `MenuItem::section(id, name, rows)` draws a grouped surface and keeps its rows in the menu's arrow-key order. `Menu::content` adds caller-authored content before the rows. A section's `.content` replaces its visible heading.

Use `MenuSurfaceStyle` with `Menu::appearance` or `MenuItem::group_appearance` to configure the surface shape, padding, spacing, border and elevations. `MenuItemStyle` overrides menu-row shapes, spacing, padding, and color roles. Use `.anchor` and `.offset` for logical trigger placement or `.position` with a window-local point. `.track_scroll` accepts a caller-owned scroll handle.

### Tooltips

`Tooltip::plain` and `Tooltip::rich` show after pointer hover or when the trigger receives keyboard focus via `.track_focus(&focus)`. For a persistent rich tooltip, create an `Entity<TooltipState>` with `cx.new(|_| TooltipState::new())` and attach it with `.persistent(&state)`. Click or activate the trigger with the keyboard, or call `state.show(cx)` from the owner. A trigger button owns its accessible Invoke action. Call `state.update(cx, |state, cx| state.show(cx))` in its `on_activate` callback so that action opens the tooltip as well. Persistent tooltips stay open when the pointer leaves. Call `state.dismiss(cx)` to close one programmatically and `is_visible()` to read its requested visibility.

`.enable_user_input(false)` leaves activation to the caller. Open tooltips can be dismissed with Escape from their trigger or content. Persistent tooltips also dismiss when a pointer presses outside. With `.on_dismiss_request(callback)`, the owner of a persistent tooltip accepts the request by calling `dismiss(cx)`. A transient tooltip closes on Escape and reports the request through the same callback. `.focus_target(&focus)` lets Tab move from the trigger to a caller-supplied control. `.focusable(true)` moves focus into the tooltip on opening. The default preserves focus. If focus is inside when the tooltip closes, it returns to the trigger or previously focused control.

Use `.title_content`, `.body_content` and `.action_content` for GPUI elements. The constructor's text provides the accessible description. `.link(label, callback)` creates a link whose callback owns navigation. `.placement(TooltipPlacement)` selects a physical side or the logical `Start` or `End`, and `.offset(pixels)` sets the gap. The default prefers `Above` with a 4 px gap and flips when the surface needs room. `.positioner(...)` can return a `TooltipPositioner` using the measured trigger bounds, viewport and text direction.

Use `.caret(TooltipCaret::default())` for the Material 16 × 8 px caret, or supply custom dimensions and a path. The caret is off by default. `.max_width`, `.shape`, `.colors`, `.tonal_elevation`, and `.shadow_elevation` configure the surface. Plain and rich tooltips default to a maximum width of 200 px and 320 px respectively within the available window. Unset colors and shape use the window's Material palette and corner roles. Tonal elevation defaults to zero and shadow elevation defaults to Level 0 for plain and Level 2 for rich.

### Scrim

Place `Scrim::new(id)` in a positioned container, after the background content and before the foreground surface. It fills the container and uses the current window theme's Scrim role at 32% opacity. Use `.color(color)` to supply a custom tint and `.opacity(value)` to multiply the tint's alpha. Values clamp to 0–1 and NaN uses the default.

By default the scrim is decorative. It dims the content while leaving pointer input and accessibility traversal available. Add `.on_click(|window, cx| ...)` to block pointer input behind the scrim and handle pointer or accessibility activation. The scrim has no keyboard tab stop. Use `.accessibility_label(label)` to name the action for assistive technology. The default label is “Dismiss overlay.” The caller owns visibility, dismissal, and the modal focus and accessibility scope. Give modal content its own keyboard dismissal action.

### App bars

`AppBar::new(id, title)` defaults to a Small app bar and uses the title as its accessible toolbar name. `.title_alignment(AppBarAlignment)` and `.subtitle_alignment(AppBarAlignment)` set independent logical Start, Center, or End alignment. The Centered variant defaults both to Center. Set `.title_max_lines(lines)` and `.subtitle_max_lines(lines)` to wrap text up to the specified number of lines. The default is one line. Use `.title_content(element)` or `.subtitle_content(element)` for rich headings. The navigation, actions, and search slots retain their own layout. Search replaces the first-row heading.

Use `.logo(element)` to replace the text in a Small or Centered app bar, place a logo above the expanded heading of a flexible app bar, or put it before search. `AppBarVariant::TwoRows` places the expanded heading below navigation and actions. `.title_for_rows(|expanded| ...)` and `.subtitle_for_rows(|expanded| ...)` build the heading for the displayed row. `.second_row(element)` adds supplemental content to the expanded heading. Keep heading, logo, and supplemental content presentation-only. Put commands in navigation or actions.

Use `.colors(AppBarColors)` to override container, scrolled container, navigation, title, subtitle, and action colors independently. Slot content inherits its color and independently styled controls keep their explicit colors. `.content_padding(AppBarPadding)` sets logical insets in each row. Set `.collapsed_height(height)` and `.expanded_height(height)` in logical pixels. The expanded height includes both rows and is at least the collapsed height. The first row can grow to fit its slots. The default collapsed height is 64 dp and flexible variants use their Material expanded dimensions. Invalid sizes fall back to defaults.

Pass `.track_scroll(&handle)` for a GPUI content scroll handle or `.scroll_state(&state)` for a retained `Entity<AppBarScrollState>`. A caller-owned state can use `set_content_offset(offset, cx)` when it supplies its own positive distance from the top. With an attached handle the handle supplies that distance. Read `content_offset()`, `height_offset()`, `height_offset_limit()`, `collapsed_fraction()`, and `overlapped_fraction()` from the state. Without an explicit strategy, a tracked flexible bar collapses by its distance from the top. Choose `.scroll_behavior(AppBarScrollBehavior::Pinned)` for a fixed height that still responds with scrolled color, `EnterAlways` to reveal on reversal, or `ExitUntilCollapsed` to stay collapsed on reversal until the content returns to the top. The linked content owns scrolling and retains its input paths. `.scroll_enabled(false)` pauses scroll-driven updates. Call `set_collapsed_fraction(fraction, cx)` to position the bar or `settle(velocity, cx)` when scrolling ends. A positive velocity chooses collapse, a negative velocity chooses expansion where the strategy permits it, and zero chooses the nearest endpoint. `.scroll_motion(MotionSpec)` overrides settling motion. Reduced motion settles immediately.

`AppBarRow::new(id, items)` and `AppBarColumn::new(id, items)` lay out horizontal or vertical actions and move items that do not fit into a Material menu. Use `AppBarItem::clickable(id, label, icon_factory)` with `.on_activate(...)` and `.disabled(bool)` for shared inline and overflow commands. Use `AppBarItem::custom(id, inline, |menu| ...)` to supply a custom inline element and its own `MenuItem`. Give items stable IDs. A custom `.overflow_indicator(|menu| ...)` supplies the visual content of the built-in keyboard-focusable trigger. Set its name with `.overflow_label(label)`. `AppBarMenuState` exposes `is_showing()`, `show(window, cx)`, and `dismiss(window, cx)`. `.max_item_count(count)` caps visible items including the trigger. The row mirrors in RTL. The hidden actions are accessible in the open menu.

### Vertical drag handle

Place `VerticalDragHandle::new(id)` on the boundary between two panes. Use `.sizes(DragHandleSizes)`, `.colors(DragHandleColors)`, and `.shapes(DragHandleShapes)` to override individual resting, pressed, and dragged values. The window theme supplies the Outline role for the 4 × 48 resting capsule and On Surface for the 12 × 52 pressed and dragged marks with Medium corners. Visual dimensions use logical pixels. The input target stays at least 48 × 48 and accommodates the largest configured mark in every state. Hover and keyboard focus add feedback while keeping their own interaction states.

Use `.on_resize(label, width, min..=max, callback)` to give the boundary a name, the current logical start pane width, bounds, and a handler for requested widths. The caller applies or rejects each request and determines the layout. Arrow keys move the focused splitter left or right, Home and End request the minimum and maximum widths, and `.keyboard_step(px(...))` changes the default 8-pixel step. Accessibility exposes the vertical divider as a named, writable range control with the role description “splitter,” because the current bridge treats its native Splitter role as read-only. The numeric value is the start pane width. The window theme maps physical mouse and touch motion to logical widths in both LTR and RTL. Escape, focus loss, and pointer cancellation end the drag. The caller keeps the last accepted width.

Pass `.interaction_source(&source)` to observe hover, press, drag, and visible keyboard focus with a shared `Entity<InteractionSource>`. Use distinct IDs when observing multiple handles. Run `cargo gallery vertical-drag-handle` to try the split-pane example.

### Scaffold

`Scaffold::new(id, content)` reserves the measured space occupied by the independent `.app_bar`, `.rail`, and `.bottom_bar` slots. The app owns those slots, the FAB and the snackbar host. Keep a stable ID and give the scaffold a bounded size. Use `.content_insets(ScaffoldInsets { top, start, bottom, end })` for the minimum distance, in logical pixels, from each scaffold edge to the usable content. Each occupied edge counts toward that minimum. The normal constructor applies any remaining padding inside the content area.

Use `Scaffold::with_layout(id, |layout, window, cx| ...)` to receive the current layout before building content. `ScaffoldContentLayout` exposes the body `bounds`, measured `occupied` space, remaining `padding`, and text `direction`. Apply only `padding` to the content or a scroll child because the scaffold already reserved `occupied`. Use `ScaffoldInsets::resolve(direction)` to convert logical start and end to physical edges. The content builder runs during layout and receives the current measurements when a slot changes size or the window resizes.

Set `.fab_position(ScaffoldFabPosition)` to `Start`, `Center`, or `End` within the available content width. `End` is the default. These positions keep the FAB above the bottom bar and above the snackbar when the snackbar slot is present. `EndOverlay` places the FAB at the scaffold's bottom edge over the bar, inside the requested bottom inset. The snackbar clears both the bottom bar and the FAB. Start and end mirror with the window direction. The FAB and snackbar are overlays, so they do not contribute to occupied content space.

### Button groups

`ButtonGroup::new(id, name, items)` uses stable item IDs and provides one Tab stop. Left and Right move focus without changing selection. Disabled members are skipped, and visual order and arrow keys follow the window direction. `.variant(ButtonGroupVariant::Connected)` joins consecutive members. Standard and Connected use a 12 and 2 logical pixel gap, respectively. `.spacing(width)` overrides the gap, `.alignment(ButtonGroupAlignment)` sets logical horizontal arrangement, and `.vertical_alignment(ButtonGroupVerticalAlignment)` defaults to Top. An item can set its own vertical alignment.

`ButtonGroupItem::new(id, name)` uses the group's `.selection(mode, selected_ids)` and `.on_change(...)` when selection is enabled. Single and Multiple allow deselection. The Required modes keep the last selected member. The application applies requests and supplies the current selection. Use `.action(callback)` for a command in any group or `.toggle(selected, callback)` for a separately controlled toggle. `.on_activate(...)` supplies a command for groups in Actions mode.

Use `.leading_icon(|| ...)` for a labeled icon button, `.icon_only(|| ...)` for an icon in place of its label, or `.content(width, || ...)` for decorative content with a preferred logical width. The constructor's name is used for accessibility and the default overflow row. `.icon_width(IconButtonWidth)` chooses the icon-only footprint. `.appearance(ButtonVariant)` and `.style(ButtonGroupItemStyle)` override the member preset, resting, pressed and checked shapes, colors, border, elevation and logical padding. `.shape(ButtonShape::Square)` switches the group from its default Round outer shape. `.connected_shapes(ButtonGroupConnectedShapes)` supplies state shapes for leading, middle, trailing or only segments. Individual shape fields take precedence.

`.weight(weight)` gives a member a proportional share of space remaining after unweighted members and minimum target widths. The default weight is zero. `.expanded_ratio(ratio)` defaults to `0.15`. A pressed member borrows width from its visible neighbors. `.compression_limit(px(...))` sets how much width a member can lend, with a default floor of 24 logical pixels. `.interaction_source(&source)` observes a visible member under `ElementId::from((group_id, item_id))` and uses the same press state for width animation. Reduced motion applies the width targets immediately.

Members that do not fit use the overflow menu. Its rows preserve member names, availability, selected states and callbacks. `.overflow_trigger(width, |open| ...)` replaces the trigger's visible content while `.overflow_label(...)` supplies its accessible name. `.overflow_content(|| ...)` adds decorative content before the generated menu rows. `.overflow_item_content(|| ...)` customizes a member's overflow row. `.overflow_open(open)` makes the owner responsible for the displayed open value. Apply requests from `.on_overflow_open_change(...)` to update it. Omitting the open value lets the group handle menu visibility.

### Split buttons

`SplitButton::new(id, leading_name, trailing_name, menu_items)` names the two segments for accessibility. The leading command uses `.on_activate(...)`. Use `.leading_icon(element)` for an icon beside the label, `.leading_icon_only(element)` for an icon in place of the label, or `.leading_content(element)` for arbitrary content. The trailing segment defaults to a menu arrow. Use `.trailing_icon(element)` for an icon sized to its tier or `.trailing_content(element)` for arbitrary trailing content. Each segment uses its most recent content setter. Keep elements in these slots presentational so each segment owns its focus, name, and activation.

The trailing segment opens the supplied menu by default and restores trigger focus when the menu closes. Use `.on_trailing_activate(callback)` for an independent command or `.trailing_toggle(selected, callback)` for a controlled toggle. The last trailing action or toggle setter wins and takes the place of the constructor menu. Toggle activation requests the next value without changing the supplied selection. `.disabled(true)` disables the leading command. `.trailing_disabled(true)` disables the trailing segment independently. An empty menu disables the default menu trigger. The segments mirror in RTL. Keyboard traversal visits the leading segment before the trailing segment.

The Filled, Filled Tonal, Elevated, and Outlined presets provide the base appearance at each Material size. `.spacing(width)` sets the gap between segments. The default is 2 dp. Use `.leading_style(SplitButtonSegmentStyle)` and `.trailing_style(SplitButtonSegmentStyle)` to override logical resting, pressed, and checked corners with `ButtonShapes`, state pigments with `ButtonColors`, stroke with `ButtonBorder`, shadows with `ButtonElevations`, and logical insets with `ButtonPadding`. Omitted fields keep the segment defaults. A selected trailing toggle or open menu uses the checked appearance. The menu trigger retains button semantics. The default checked shape rounds the inner trailing corners. Checked colors fall back to the enabled colors, and disabled colors take precedence. Reduced motion applies the resulting shape immediately.

Pass caller-owned entities through `.leading_interaction_source(&source)` and `.trailing_interaction_source(&source)` to observe either segment. They report under `ElementId::from((id, "primary"))` and `ElementId::from((id, "secondary"))` respectively. The same entity can observe both keys. Replacing an attachment clears that segment's snapshot from its previous source.

### Scroll fields

Create one `Entity<ScrollFieldState>` per field with `cx.new(|cx| ScrollFieldState::new(item_count, index, cx))` and pass it to `ScrollField::new(id, name, &state)`. Call `selected_option()` to read the option closest to the center, `target_option()` for the destination, and `is_scroll_in_progress()` while scrolling or settling. Observe the entity to update other views. `scroll_to_option(index, cx)` moves immediately and `animate_scroll_to_option(index, cx)` follows the window's motion scheme and system reduced motion. Both clamp an out-of-range index. `set_item_count(count, cx)` adjusts the available options and clamps the destination. A count of zero leaves the field empty with no selected or target option.

The field centers the current option within a three-row viewport. Click a row or use the wheel, touchpad, Up and Down keys, or accessibility actions to change the selection. The wheel wraps from the last item to the first and back. Pass `.item_content(|index, selected, enabled| ...)` to render a decorative GPUI element for a row. The default content pads the index to at least two digits. The constructor's name labels the field, and `.value_description(|index| ...)` describes the destination for assistive technology while the field scrolls and the centered option at rest. Give the field a name that describes its purpose and bounds where useful.

Use `.colors(ScrollFieldColors)` to override the container, option, and selected option colors for enabled and disabled states. The default palette uses `SurfaceContainerLowest`, `Outline`, and `OnSurface`. `.disabled(true)` settles an active user scroll and prevents further user changes. The caller can still position the field through its state. Attach a caller-owned `InteractionSource` with `.interaction_source(&source)` to observe the field's interaction presentation independently of its selection.

### Carousels

Use `Carousel::new(id, label, items)` with stable, unique item IDs. Create an optional `Entity<CarouselState>` with `cx.new(|_| CarouselState::new(initial_index))` and attach it with `.state(&state)`. Observe the entity to read `current_item()`, `current_item_id()`, and the signed `current_item_offset_fraction()` from the nearest item. The position follows the target ID when items move and falls back to its clamped former index if the target is removed. The initial index and requests made while empty take effect when items arrive. Use `scroll_to_item(index, cx)` to jump or `animate_scroll_to_item(index, cx)` to follow the window motion policy. Both clamp to the available indices. Use one state per carousel. Without an attached state the carousel retains its position under its element ID.

Set `.alignment(CarouselAlignment::Start)` or `.alignment(CarouselAlignment::Center)` for Multi-browse, Hero, and Centered Hero. Centered Hero defaults to the center and the other contained layouts to the leading edge. All six layouts support `.item_spacing(px(...))` and `.content_padding(CarouselPadding { start, end, top, bottom })`. Start and end are logical edges. Horizontal layouts default to 8 px spacing, 16 px leading padding, and 8 px cross-axis padding. Contained layouts also have 16 px trailing padding. Full-screen defaults to 16 px spacing and zero padding. `.small_item_widths(min, max)` sets positive bounds for small keylines, which default to 40–56 px. A narrow viewport can reduce the layout to one focal item.

`.user_scroll_enabled(false)` turns off wheel, trackpad, keyboard navigation, and accessibility scrolling. Item activation and programmatic navigation remain available. By default the contained layouts and Full-screen snap to the nearest keyline. Uncontained layouts scroll freely unless `.snap_scrolling(true)` is set. `.fling_behavior(...)` chooses free scrolling, nearest snapping, single-item advance, or a custom resting item computed from `CarouselFlingContext`. Line-wheel detents and accessibility scroll commands request discrete items. Animated positioning and snapping honor reduced motion.

Wrap arbitrary content in `CarouselParallax::new(content)` inside a scrollable layout. The effect uses the current GPUI clip bounds as the viewport, or window-coordinate bounds passed to `.viewport(bounds)`. Use `.axis(Axis::Vertical)` for a vertical layout. As the item enters or exits, the effect progressively clips and translates its content without changing its layout size. Reduced motion keeps the viewport clip and skips the additional parallax translation. Use `.shape(CornerShape)` and `.border(CarouselBorder)` for matching corner geometry and a border. GPUI clips content to rectangular bounds. Rounded corners are covered with the Material Surface color or an opaque `.backdrop(color)`. Match this color to a uniform parent background. Use square corners to keep patterned or transparent backgrounds visible.
