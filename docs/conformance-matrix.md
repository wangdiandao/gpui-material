# Component conformance matrix

English | [中文](conformance-matrix.zh.md)

This matrix tracks per-component conformance and verification maturity for every component documented in [Components](component.md) against the [pinned Material 3 baseline](design-sources.md#material-specification) and [Platforms and quality requirements](verification.md). It distinguishes what is merely compiled and rendered from what is covered by repeatable automated tests and what has completed full native release acceptance.

> Compilation, type-checking, or rendering a Gallery preview alone **never** qualifies a component as `Verified` or `Production Ready`.

<a id="成熟度定义与晋级门槛"></a>

## Maturity definitions and promotion gates

| Maturity | Definition | Required evidence | Does not qualify |
| --- | --- | --- | --- |
| `Implemented` | Public API compiles and renders in its owning crate and Gallery (or opt-in window mode), but automated verification of documented variants, states, accessibility, or directional/motion rules is missing or incomplete. | Public API in `crates/` plus Gallery story or opt-in preview. | Compilation alone, smoke clicks without behavior assertions, or partial unit tests without component interaction checks. |
| `Verified` | Documented variants, interaction and value states, accessibility semantics (role, name, value, state, focus, keyboard/semantic actions), and applicable RTL, reduced-motion, and theme rules are covered by repeatable automated tests in CI. | Repeatable unit tests in `crates/` and/or headless GPUI tests in `apps/gallery/src/` running in [Engineering CI](../.github/workflows/ci.yml), with traceable Gallery story and test file links. | Headless paint/quad assertions alone do not prove real-window pixel fidelity, screen-reader announcements, or native IME candidate positioning. |
| `Production Ready` | Satisfies every `Verified` gate **plus** recorded Windows 11 x64 real-window visual acceptance, native assistive technology and IME acceptance, and applicable performance verification with no open conformance blockers. | All `Verified` tests green **plus** a linked Issue or PR recording Windows 11 x64 real-window visual checks (light/dark, scaled fonts, narrow width, high DPI), UI Automation, Narrator, Microsoft Pinyin IME (where applicable), and reproducible performance baselines per [verification](verification.md) and [rendering performance](development.md#rendering-performance). | Unrecorded manual spot-checks, headless-only runs, unrun `#[ignore]` benchmarks, or open conformance defects. |

Promotion is strictly cumulative:

- `Implemented` → `Verified`: close automated gaps in variants, state transitions, disabled/error/cancellation edge cases, RTL/reduced-motion rules, and headless accessibility semantics, and trace the test files in the matrix.
- `Verified` → `Production Ready`: complete and record Windows 11 x64 real-window visual checks, native UI Automation and Narrator verification, Microsoft Pinyin composition and candidate positioning (for text-entry and overlay paths), and performance verification (frame profile, idle redraw, virtualization, or benchmark baseline as applicable) in the corresponding Issue or PR, then link that record in the matrix row.

<a id="覆盖维度说明与审计规则"></a>

## Coverage legend and audit policy

Each row in the tables below records eight fields audited directly against the repository's public APIs, [Gallery stories](../apps/gallery/src/story.rs), and tracked test files:

- **Component**: Public Rust type(s), owning crate or Cargo feature, and Gallery story ID (`cargo gallery <id>`).
- **Maturity**: Current maturity level (`Implemented`, `Verified`, or `Production Ready`).
- **Spec variants**: Material 3 and desktop-adapted variants from [Components](component.md) exercised by automated tests.
- **States**: Interaction, value, disabled/error/dragged, RTL, reduced-motion, and IME composition states covered by tests.
- **Accessibility**: Automated role, name, value, state, focus, and keyboard/semantic-action checks (`gpui_base::test_support` / `accesskit`) versus unverified real screen-reader (Narrator) and UI Automation checks.
- **Visual & Gallery**: Headless paint, quad, stroke, clip, bounds, and scale-factor assertions plus Gallery preview coverage. Per [Platforms and quality requirements](verification.md), Windows visual pixel acceptance requires a real window and is tracked separately from headless paint assertions.
- **Performance**: Automated idle-frame stop assertions (`window.simulate_next_frame(cx) == 0`), viewport virtualization/overscan checks, shaping/snapshot cache checks, or release microbenchmarks (`ripple_clip_benchmark`, `--frame-profile`) versus unmeasured real-window frame baselines.
- **Test references & promotion gaps**: Exact relative links to test files in `crates/` and `apps/gallery/src/` plus the concrete remaining gates required for promotion.

Cross-cutting foundation suites shared across components live in [theme color reference](../crates/theme/tests/color_reference.rs), [theme tokens](../crates/theme/tests/theme.rs), [foundation shape & ripple benchmark](../crates/foundation/src/shape.rs), [foundation feedback](../crates/foundation/src/feedback.rs), [foundation motion](../crates/foundation/src/motion.rs), [Gallery theme propagation](../apps/gallery/src/theme_tests.rs), [Gallery desktop integration](../apps/gallery/src/desktop_tests.rs), [Gallery drawing](../apps/gallery/src/drawing.rs), and [Gallery input adapters](../apps/gallery/src/input_examples.rs).

## Maintenance and promotion workflow

Keep this matrix synchronized with code and verification status in every PR that adds, changes, or verifies a component:

1. **New components or variants**: Add or update the corresponding row in both `docs/conformance-matrix.md` and `docs/conformance-matrix.zh.md`. If a PR adds a documented variant or state without automated tests, reflect the gap honestly rather than leaving an inflated `Verified` claim.
2. **Promoting `Implemented` → `Verified`**: Add repeatable unit tests in `crates/` and/or headless GPUI tests in `apps/gallery/src/` covering all documented variants, interaction/value states, accessibility semantics, RTL, and reduced motion. Link the new test files directly in the matrix row.
3. **Promoting `Verified` → `Production Ready`**: Execute the applicable Windows 11 x64 real-window visual, UI Automation, Narrator, Microsoft Pinyin IME, and performance baseline checks described in [Platforms and quality requirements](verification.md) and [Development and verification](development.md#rendering-performance). Record the commit hash, environment, scenarios, measurements, and exceptions in the corresponding Issue or PR — do **not** commit separate evidence documents, logs, or screenshots to the repository — and link that Issue or PR in the matrix row.
4. **Refresh documentation checks**: Stage edited Markdown files, update bilingual fingerprints, and run workspace verification:

```powershell
git add docs/conformance-matrix.md docs/conformance-matrix.zh.md
cargo xtask docs --write docs/conformance-matrix.md
cargo xtask check
cargo test --locked --workspace --all-features
cargo test --locked -p gpui-material-gallery --features test-support
```
