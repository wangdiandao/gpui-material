# 组件一致性矩阵

[English](conformance-matrix.md) | 中文

本矩阵对照[锁定的 Material 3 规范](design-sources.zh.md#material-specification)与[平台与质量要求](verification.zh.md)，逐一跟踪[组件](component.zh.md)文档中全部组件的一致性与验证成熟度，严格区分“仅编译可渲染”“已通过自动化验证”与“已完成生产验收”三个阶段。

> 仅通过编译、类型检查或在 Gallery 中渲染预览，**绝不**构成 `Verified` 或 `Production Ready`。

<a id="maturity-definitions-and-promotion-gates"></a>

## 成熟度定义与晋级门槛

| 成熟度 | 定义 | 晋级必需证据 | 不满足条件的情况 |
| --- | --- | --- | --- |
| `Implemented` | 公开 API 已在所属 crate 与 Gallery（或可选窗口模式）中编译并渲染，但已文档化变体、状态、无障碍语义或方向/动效规则的自动化验证缺失或不完整。 | `crates/` 中的公开 API，以及对应的 Gallery 示例或可选预览入口。 | 仅能编译通过、缺少行为断言的冒烟点击，或仅有部分纯逻辑单测而缺少组件交互测试。 |
| `Verified` | 已文档化的变体、交互与值状态、无障碍语义（角色、名称、值、状态、焦点、键盘与语义动作），以及适用的 RTL、低动效与主题规则，均已由 CI 中可复现的自动化测试覆盖。 | 在[工程 CI](../.github/workflows/ci.yml) 中运行的可复现 `crates/` 单元测试与/或 `apps/gallery/src/` 无头 GPUI 测试，并可追溯到 Gallery 示例与具体测试文件。 | 仅靠无头绘制/矩形断言不足以证明实窗像素一致性、真实读屏播报或原生输入法候选定位。 |
| `Production Ready` | 满足 `Verified` 的全部门槛，**并且**已完成且记录了 Windows 11 x64 真实窗口视觉验收、真实辅助技术与中文输入法验收以及适用的性能基线验证，且无未关闭的一致性阻塞项。 | 全部 `Verified` 测试通过，**并且**在关联 Issue 或 PR 中记录了 Windows 11 x64 实窗视觉检查（浅深主题、缩放字体、窄窗、高 DPI）、UI Automation、讲述人（Narrator）、微软拼音 IME（适用场景），以及符合[验证要求](verification.zh.md)与[渲染性能](development.zh.md#rendering-performance)的可复现性能基线。 | 未留痕的口头手测、仅无头测试通过、未运行的 `#[ignore]` 基准测试，或仍存在未解决的一致性缺陷。 |

成熟度晋级严格遵循递进原则：

- `Implemented` → `Verified`：补齐变体、状态转移、禁用/错误/取消边界、RTL/低动效规则以及无头无障碍语义的自动化测试，并在矩阵中关联测试文件。
- `Verified` → `Production Ready`：在对应 Issue 或 PR 中完成并记录 Windows 11 x64 实窗视觉检查、原生 UI Automation 与讲述人验证、微软拼音预编辑与候选框定位（针对输入与浮层路径），以及适用的性能验证（帧剖析、静止零重绘、虚拟化或微基准基线），随后在矩阵对应行中关联该验收记录。

## 覆盖维度说明与审计规则

下表每行均直接对照仓库公开 API、[Gallery 示例目录](../apps/gallery/src/story.rs)及已跟踪测试文件审计，包含八个字段：

- **组件**：公开 Rust 类型、所属 crate 或 Cargo 特性，以及 Gallery 示例 ID（`cargo gallery <id>`）。
- **成熟度**：当前成熟度等级（`Implemented`、`Verified` 或 `Production Ready`）。
- **规范变体**：[组件](component.zh.md)中记录的 Material 3 及桌面适配变体里，已被自动化测试覆盖的范围。
- **状态覆盖**：测试覆盖的交互、值、禁用/错误/拖拽、RTL、低动效与 IME 组合状态。
- **无障碍覆盖**：自动化角色、名称、值、状态、焦点与键盘/语义动作断言（`gpui_base::test_support` / `accesskit`），以及尚未验证的真实读屏（讲述人）与 UI Automation 项。
- **视觉测试与 Gallery**：无头绘制、矩形、描边、裁剪、边界与缩放因子断言，以及 Gallery 示例覆盖。依据[平台与质量要求](verification.zh.md)，Windows 视觉像素验收必须在真实窗口完成，与无头绘制断言分开记录。
- **性能覆盖**：自动化静止零重绘断言（`window.simulate_next_frame(cx) == 0`）、视口虚拟化/预渲染断言、排版/快照缓存检查或 Release 微基准（`ripple_clip_benchmark`、`--frame-profile`），以及尚未测量的实窗帧基线。
- **测试索引与晋级缺口**：指向 `crates/` 与 `apps/gallery/src/` 中实际测试文件的相对链接，以及晋级下一阶段所需的具体缺口。

跨组件共享的基础设施测试套件位于[主题色参考测试](../crates/theme/tests/color_reference.rs)、[主题 Token 测试](../crates/theme/tests/theme.rs)、[基础形状与涟漪基准](../crates/foundation/src/shape.rs)、[基础反馈测试](../crates/foundation/src/feedback.rs)、[基础动效测试](../crates/foundation/src/motion.rs)、[Gallery 主题传播测试](../apps/gallery/src/theme_tests.rs)、[Gallery 桌面集成测试](../apps/gallery/src/desktop_tests.rs)、[Gallery 绘制测试](../apps/gallery/src/drawing.rs)和[Gallery 输入适配器测试](../apps/gallery/src/input_examples.rs)。

<a id="maintenance-and-promotion-workflow"></a>

## 维护与晋级流程

每当 PR 新增、修改或验证组件时，应同步更新本矩阵：

1. **新增组件或变体**：同步更新 `docs/conformance-matrix.md` 与 `docs/conformance-matrix.zh.md` 的对应行。若 PR 新增了文档化变体或状态但尚未补齐自动化测试，必须如实标出缺口或保持在 `Implemented`，不得虚标 `Verified`。
2. **从 `Implemented` 晋级至 `Verified`**：在 `crates/` 和/或 `apps/gallery/src/` 中补充可复现的单元测试与无头 GPUI 测试，覆盖已文档化变体、交互与值状态、无障碍语义、RTL 与低动效规则，并在矩阵对应行中直接链接新增测试文件。
3. **从 `Verified` 晋级至 `Production Ready`**：按[平台与质量要求](verification.zh.md)与[开发与验证](development.zh.md#rendering-performance)完成适用的 Windows 11 x64 实窗视觉、UI Automation、讲述人、微软拼音 IME 与性能基线验证。将提交哈希、环境、场景、测量结果与例外范围直接记录在对应 Issue 或 PR 中——**不要**向仓库提交独立的证据文档、日志或截图——并在矩阵对应行中链接该 Issue 或 PR。
4. **刷新文档检查**：暂存修改的 Markdown 文件，更新双语指纹，并运行工作区校验：

```powershell
git add docs/conformance-matrix.md docs/conformance-matrix.zh.md
cargo xtask docs --write docs/conformance-matrix.md
cargo xtask check
cargo test --locked --workspace --all-features
cargo test --locked -p gpui-material-gallery --features test-support
```
