# P1 能力验证与架构冻结

P0 冻结后进入 P1。各探针在 `experiments/` 中使用独立临时 Cargo 项目与 lockfile，可共享小型测试宿主。用基础原语、数值样本和中性测试控件验证机制，随后保留可复现步骤、失败样本、日志、截图和架构结论。依赖采用 [P0 固定组合](../design/sources.md#gpui-与-base)和[候选依赖](../architecture/index.md#候选依赖)。

| 探针 | 依赖 | 场景 | 通过与阻塞判据 |
| --- | --- | --- | --- |
| P1-01 构建与包身份 | 无 | 用精确版本解析 Base/GPUI，三平台建立窗口并启用隔离 test-support。记录 metadata、feature 图、工具链与运行命令。 | 每平台可复现，GPUI/平台包分别只有一个身份，theme 候选的依赖图与 GUI 隔离。版本漂移、身份冲突、必要后端缺失均阻塞。 |
| P1-02 激活、焦点与取消 | P1-01 | 用 Base 原语验证指针/Enter/Space、禁用切换、指针移出与捕获丢失、Tab/Shift+Tab、roving focus、按键重复。 | 业务动作一次、焦点与视觉输入来源可辨、拖动取消后状态复位。缺少公共状态或出现残留激活时需可验证适配或上游补丁。 |
| P1-03 输入与文本度量 | P1-01 | 真实中文 IME 预编辑、确认、取消及候选定位；失焦、浮层内输入、选区、剪贴板、密文和字体回退。 | 三平台组合及候选位置随 DPI/滚动更新，安全字段语义值不泄露明文，度量与绘制可对齐。必需文本路径失败即阻塞。 |
| P1-04 原生语义 | P1-01、P1-02、P1-03 | 验证基础动作、可切换值、范围、编辑、浮层和状态提示的角色、名称、值、焦点、关系、动作与通知。 | 三平台的语义快照、真实系统树及读屏路径均有证据。同一业务动作经辅助技术执行一次。必要桥接缺失或不可达即阻塞。 |
| P1-05 形状、绘制与 ripple | P1-01、P1-02 | 对照固定 graphics-shapes，使用 polymorpher 候选与 GPUI 路径，比较闭合、几何、填充、裁剪、阴影、命中和 ripple 起点。 | 记录误差尺度及接受范围，几何边界与输入一致，高 DPI 下边缘和状态层可验证。形变退化、裁剪/命中无法对齐或必须额外引入渲染后端时复核实现路径。 |
| P1-06 动效与系统偏好 | P1-01、P1-05 | 比较 spring 与重定向，区分几何与颜色/透明度；快速反转、退出重入、系统低动效与静止重绘。 | 轨迹连续，系统偏好能生效，收敛后停止动画额外重绘。必须复刻调度机制或无法满足静止/低动效时阻塞。 |
| P1-07 浮层、滚动与窗口 | P1-01、P1-02 | 验证嵌套浮层层级、边缘避让、Esc、点击外部、焦点恢复、值标签、嵌套滚动与拖动所有权。 | 层级、回焦、滚动、LTR/RTL 放置、窗口变动及拖动取消路径可由基础契约实现。模态或滚动所有权无法可靠保持时阻塞。 |
| P1-08 主题与纯算法 | P1-01 | 两窗口切换 App 主题和局部组件覆盖，列举 Base 的读取路径；对照 MCU 测试检查 Rust 候选的动态角色，核对 chrono/Calendar 边界和 feature 图。 | 两窗口的 App 投影一致，渲染期间无需修改 App 全局；算法差异有可行的窄适配或替代路径。颜色、日期必需能力无法达到或纯主题必须依赖 GPUI 时阻塞。 |
| P1-09 架构与证据评审 | P1-01–08 | 汇总通过证据、平台限制、候选依赖、性能与实际 API，修订正式架构文档。 | 所有必需探针通过，必要补丁已纳入可复现的解析并回归，固定 DAG 和依赖边界可供 P2 使用。 |

各探针使用[验证环境与证据格式](../verification.md)。遇到必需能力缺口时，记录上游版本、最小复现、影响平台、替代接口、风险与证据。通用修复关联上游 Issue/PR 和发布版本，验证过的过渡依赖注明来源和退出条件。P2 从已冻结的架构与依赖结论开始。
