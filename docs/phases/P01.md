# P1 Capability probes and architecture freeze

English | [中文](P01.zh.md)

P1 starts after P0 freezes. Each probe uses an isolated temporary Cargo project and lockfile under `experiments/` and can share a small test host. Use basic primitives, numeric fixtures, and neutral controls. Record reproduction steps and results in the associated issue or PR. The initial release and required phase acceptance use Windows 11 x64/MSVC. macOS and Linux results inform future support evaluations. [P0 version pairing](../design-sources.md#gpui-and-base) · [Candidate dependencies](../architecture.md#candidate-dependencies) · [P1 acceptance PR](https://github.com/wangdiandao/gpui-material/pull/51)

| Probe | Dependencies | Scenario | Passing criteria and blockers |
| --- | --- | --- | --- |
| P1-01 Build and package identity | None | Resolve exact Base/GPUI versions, create a Windows window, and enable isolated test-support. Record metadata, feature graphs, toolchain, and commands. | Windows is reproducible, GPUI and platform each resolve one identity, and theme candidates are independent of the GUI. Version drift, identity conflicts, or a missing required backend block the phase. |
| P1-02 Activation, focus, and cancellation | P1-01 | Use Base primitives for pointer, Enter, Space, changing disabled state, pointer exit and capture loss, Tab/Shift+Tab, roving focus, and key repeat. | Activate once, distinguish focus and input source, and reset after drag cancellation. Missing public state or lingering activation requires a verified adapter or upstream patch. |
| P1-03 Input and text measurement | P1-01 | Test real Chinese IME preedit, commit, cancellation, and candidate placement, plus blur, input in overlays, selection, clipboard, masking, and font fallback. | Windows composition and candidate positioning follow DPI and scrolling. Secure semantic values hide plaintext. Measurement and drawing align. Required text path failures block the phase. |
| P1-04 Native semantics | P1-01, P1-02, P1-03 | Verify roles, names, values, focus, relationships, actions, and announcements for activation, toggles, ranges, edits, overlays, and status. | Check semantic snapshots, UI Automation, and Narrator on Windows. Assistive technology activates the action once. Missing or unreachable bridges block the phase. |
| P1-05 Shape, drawing, and ripple | P1-01, P1-02 | Compare pinned graphics-shapes with polymorpher and GPUI paths for closure, geometry, fill, clipping, shadow, hit testing, and ripple origin. | Record error scale and tolerance. Match geometry and input boundaries and verify high-DPI edges and state layers. Reevaluate degenerate morphs, misaligned clipping or hit testing, or a required additional renderer. |
| P1-06 Motion and system preferences | P1-01, P1-05 | Compare spring behavior and retargeting for geometry, color, and opacity. Exercise rapid reversal, exit and reentry, system reduced motion, and idle redraw. | Preserve trajectory continuity, honor system preference, and stop animation redraws at rest. A required scheduler reimplementation or inability to meet idle or reduced-motion behavior blocks the phase. |
| P1-07 Overlays, scroll, and windows | P1-01, P1-02 | Verify nested layering, edge avoidance, Esc, outside click, focus restoration, value labels, nested scrolling, and drag ownership. | Base contracts can implement layering, focus, scroll, LTR/RTL placement, window changes, and drag cancellation. Unreliable modal or scroll ownership blocks the phase. |
| P1-08 Theme and pure algorithms | P1-01 | Switch the app theme and local overrides across two windows, list Base read paths, compare dynamic roles against MCU tests, and check chrono/Calendar boundaries and features. | Both windows see consistent app projection without changing globals during rendering. Algorithm discrepancies have a narrow adapter or alternative. Missing required color or date behavior or a GPUI dependency in pure theme blocks the phase. |
| P1-09 Architecture and verification review | P1-01–08 | Review probe results, platform limits, candidates, performance, and real APIs, then revise the architecture. | Required probes pass, necessary patches resolve reproducibly and pass regression checks, and P2 can use the pinned dependency DAG and boundaries. |

Follow the [platform and verification requirements](../verification.md). For a required gap, record the upstream version, a minimal reproduction, affected platforms, alternative interfaces, and risks in the issue. Link upstream fixes to the issue, PR, and release. Record the source and removal criteria for verified temporary dependencies. P2 starts from the frozen architecture and dependency decisions.
